# surveyquorum

Консенсусная отбраковка респондентов в опросах. Quorum прогоняет ответы через независимые
проверки и помечает респондента только тогда, когда несколько из них сходятся. У каждого
вердикта есть улики, а при желании — текст жалобы в панель с одной причиной.

**Статус: открытая бета, v0.1.** Механизм, который лежит в основе этого репозитория, работает в
продакшене одной платформы опросов. Здесь опубликована его первая платформонезависимая версия:
движок, веса и пять скиллов, перенесённые и проверенные на синтетическом демо с регрессионными
тестами. Несколько производственных методов, пока завязанных на одну платформу, выйдут в следующих
релизах, а перемер на проде именно этого кода — следующий шаг. Правки приветствуются — откройте
issue или pull request. В разделах «Статус» и «Что пока не выложено» ниже — что измерено, что
предположено и что дальше.

## Принцип кворума

Детекторы не выносят решений. Каждый выдаёт улики — именованный сигнал с силой, — а
взвешенный слой превращает улики о респонденте в один из трёх исходов:

| исход | смысл |
|---|---|
| `block` | сошлись два или больше сильных независимых сигнала, либо несколько слабых дают ту же уверенность — решение, которому второй взгляд не нужен |
| `review` | один сигнал или только слабые — второй взгляд, LLM-арбитра или человека |
| `keep` | ничего, либо только положительные улики |

Вес каждого сигнала — измеренное отношение правдоподобия, ограниченное так, что **одиночный
сигнал всегда останавливается на `review`**. Это и есть принцип, записанный арифметикой; формула
и пороги — в `docs/weights.md`.
Сигналы, которые срабатывают у большой доли когорты на одном и том же вопросе, сообщаются
автору анкеты как *артефакты дизайна* и веса не имеют: сводка прогона печатает по строке на
каждый затронутый вопрос (`design artifact: prototype task '…' — 16 respondents (16% of the
cohort) gave up with no clicks; the prototype likely did not load`), а в `verdicts.json` те же
строки лежат в `designArtifactSummary`.

Десять детекторов. Восемь статистических, без LLM: темп по вопросам, повторы в открытых, шаблон
в матрицах, массовый выбор, усилие в прототипе, выход с сайта, согласие в карточной сортировке,
первый клик. Два на LLM: классификация открытых ответов и согласованность ответов. Обзор —
`docs/detectors.md`; README рядом с каждым статистическим детектором — подробности, LLM-детекторы
заданы своими промптами.

## Три способа входа

Один движок, три способа дать ему модель. Нужны Node 20+ и клон репозитория (в npm пока нет —
см. «Статус»).

**1. Внутри агента для кода, только с подпиской.** Самый простой старт: киньте ссылку на этот
репозиторий своему Claude Code, Codex, Cursor или Gemini CLI и попросите обычными словами, например
*«спроектируй скрининг для моей аудитории скиллом screener-design из
https://github.com/Rogeres/surveyquorum»* или *«проверь ответы в answers.csv через surveyquorum»*. Агент прочитает `AGENTS.md` и скиллы, сам
склонирует и установит что нужно и сделает остальное; вы только отвечаете на его вопросы. Внутри
модель — сам агент: CLI записывает нужные LLM-суждения в файл, агент на них отвечает, `resume`
завершает прогон.

```bash
git clone https://github.com/Rogeres/surveyquorum.git && cd surveyquorum && npm install
# сначала механика: все суждения берутся из поставляемого кэша, ничего не ждёт ответа
npm run surveyquorum -- run examples/demo-dataset.json --llm agent --llm-cache examples/llm-cache
# на своих данных модель — сам агент:
npm run surveyquorum -- run dataset.json --llm agent
#  → .surveyquorum/judge-requests.jsonl + инструкция для агента
#  агент дописывает ответы в .surveyquorum/judge-responses.jsonl, затем:
npm run surveyquorum -- resume
```

Скиллы в `skills/` оборачивают этот путь (ставятся как плагин Claude Code из
`.claude-plugin/` или копированием папки скилла в каталог правил другого агента).

**2. CLI с API-ключом или локальной моделью.** OpenAI-совместимые эндпоинты (OpenAI, Yandex
Cloud, OpenRouter, Ollama), Anthropic. Без ключа восемь статистических детекторов работают.

```bash
export SURVEYQUORUM_LLM_PROVIDER=openai-compatible SURVEYQUORUM_LLM_API_KEY=... \
       SURVEYQUORUM_LLM_MODEL=gpt-4.1-mini SURVEYQUORUM_LLM_ARBITER_MODEL=gpt-4.1
npm run surveyquorum -- convert export.csv --mapping my-mapping.json --out dataset.json
npm run surveyquorum -- run dataset.json --arbiter --out verdicts.json   # после перекалибровки: --weights my-weights.json
npm run surveyquorum -- explain verdicts.json <responseId>
npm run surveyquorum -- complaints verdicts.json --dataset dataset.json --lang ru
# reason codes / token rule of your panel: --panel-profile my-panel.json (adapters/panel-profiles/)
```

**3. Как библиотека** (`packages/core`, пакет `surveyquorum`). Пакет указывает на
`packages/core/dist`, который `npm install` собирает через корневой скрипт `prepare`; если
`dist/` нет (установка с `--ignore-scripts`, свежий клон без установки), сначала соберите:

```bash
npm run build          # собирает packages/core/dist и packages/cli/dist
```

```ts
// screen.mjs in the repository root; run with: node screen.mjs
import { readFileSync } from 'node:fs';
import { parseDataset, run } from 'surveyquorum';
const dataset = parseDataset(JSON.parse(readFileSync('examples/demo-dataset.json', 'utf8')));
const results = await run(dataset, { minCohort: 30 }); // для LLM-детекторов добавьте `llm: createLlmClient(cfg)`
for (const v of results[0].verdicts) console.log(v.responseId, v.outcome, v.probability);
```

Провайдеры, переменные окружения и файл конфигурации: `docs/models.md`. Как привести чужой
CSV к входному контракту: `adapters/README.md`.

### Импорт из Pathway

Pathway — платформа опросов и UX-исследований; платформа автора и единственная система со
встроенным импортом на сегодня. Всё остальное заходит через `convert` с пресетом или маппингом.

```bash
PATHWAY_API_TOKEN=... npm run surveyquorum -- import pathway --test <test-id> --out dataset.json
```

CSV-экспорт отчёта Pathway распознаётся по заголовку и конвертируется без маппинга
(`npm run surveyquorum -- convert report.csv`), как и общая «длинная» раскладка flat-long
(`adapters/presets/flat-long.json`). Подробности: `adapters/presets/pathway.md`.

## Что показывает демо

В `examples/` — три синтетических опроса, 300 выдуманных респондентов, за каждым известная
персона. LLM-суждения — и детекторов, и арбитра — берутся из `examples/llm-cache/`, поэтому весь
конвейер идёт без ключа:

```bash
npm run surveyquorum -- run examples/demo-dataset.json --llm-cache examples/llm-cache --arbiter
```

| | респондентов | заблокированы | человеку | оставлены |
|---|---:|---:|---:|---:|
| подсаженные нарушители (10 персон) | 64 | 54 | 4 | 6 |
| честные (4 персоны, включая мат по делу, «не знаю», один быстрый клик) | 236 | 0 | 3 | 233 |

54 из 64 подсаженных нарушителей заблокированы; ни один честный не заблокирован; 7 респондентов
переданы человеку, потому что судьи засомневались, — 4 подсаженных нарушителя и 3 честных. Из 6
оставленных нарушителей троих отпустил арбитр с названной причиной (их открытые ответы он счёл
настоящими), а трое до него не дошли: «массовый выбиральщик» в почти нормальном темпе и два
случайных сортировщика, чья раскладка лежит в пределах двух стандартных отклонений от общей,
показывают один слабый паттерн или ни одного, и движок намеренно их оставляет.

До арбитра движок сам блокирует 18 нарушителей и просит второго взгляда на 43 — и ещё на 5
честных, персону с одним быстрым блоком: один сигнал, значит второй взгляд, а не блок. Арбитр и
есть этот второй взгляд. Из 43 он подтверждает 36 и тем замыкает их кворум, троих отпускает с
причиной и четверых передаёт человеку; из 5 честных двоих отпускает и троих передаёт человеку.
Медленные «шаблонщики» и «массовые выбиральщики» доходят до него как случаи с одним сигналом,
потому что их паттерн тянется через весь опрос — long-string-индекс из литературы о небрежных
ответах, сильный сам по себе, — но один сигнал не кворум, пока с ним не согласился независимый
судья. 12 честных, у которых не загрузился прототип, отражены одной строкой артефакта дизайна для
автора анкеты (16 респондентов на этом задании, считая 4 подсаженных «сдавшихся»), а не
двенадцатью банами. Когда арбитр сомневается, смотрит человек; ничего, в чём он не уверен, не
отпускается молча. Без `--arbiter` прогон останавливается на раскладке движка (block 18, review
48, keep 234); измеренное поведение мягкого режима описано в `docs/arbiter.md`.

## Статус

v0.1, открытая бета. Первая публичная версия производственного механизма; интерфейс ещё может
меняться между релизами. Клонируйте и запускайте; npm-пакеты `surveyquorum` / `surveyquorum-cli`
зарезервированы под v0.2.

Измерено (прод, июль–сентябрь 2026, одна платформа панельных исследований, поток в несколько сотен
тысяч ответов; подтверждение — LLM-арбитром, чьё согласие с людьми-проверяющими описано в
`docs/arbiter.md`): веса 23 сигналов, лестница точности по числу согласных сигналов (1 → 23 %,
2 → 55 %, 3 → 80 %, 4+ → 91 %), лестница темпа, согласие арбитра с людьми. Предположено, до
перекалибровки: 7 сигналов детекторов карточной сортировки, первого клика, сайта и массового
выбора — помечены `assumed` в `weights.json`, чтобы перекалибровка заменила их первыми. Веса и
лестницы получены из продовых измерений; этот порт проверен на синтетическом демо и его
регрессионных тестах, а перемер на проде именно этого кода — следующий шаг. Каждая цифра — в
`docs/numbers.md`, процедура перекалибровки — в `docs/weights.md`. Дорожная карта: история
респондента между опросами, ось «соответствие аудитории», сервис без установки для пути без кода.

## Что пока не выложено

Несколько методов из производственной системы намеренно не вошли в v0.1: они пока зависят от одной
платформы, и их нужно переосмыслить платформонезависимо, прежде чем публиковать:

| метод | что делает | почему ждёт |
|---|---|---|
| история респондента | повторные нарушения между опросами по отпечатку устройства или идентификатору панели | нужен стабильный ключ респондента, который может дать любой источник, и хранилище истории; поля в контракте уже есть, в плане интерфейс `ReputationStore` |
| соответствие аудитории | сверка ответов с тем, кого должны были опросить: заявленный на скрининге профиль против ответов в теле анкеты | нужны заказ на найм и ответы скрининга, которых в большинстве экспортов нет |
| ответы, сделанные с использованием ИИ | выявляет ответы, подготовленные с помощью ИИ-ассистента | нужен механизм на фронтенде опроса, фиксирующий, как ответ введён: набор, вставка, диктовка |
| сервис без установки | статистические детекторы как размещённая страница, ставить ничего не нужно | после стабилизации CLI |

Опубликованные цифры ни один из этих методов не предполагают: каждое число в `docs/numbers.md` получено
детекторами, которые лежат в этом репозитории.
